# DeepSeek 余额托盘监控

一个常驻 Windows 托盘的小工具：**没有主窗口**，只有一个托盘图标。悬停就能看到
DeepSeek 账户可用余额、峰谷时段与接口状态，右键能看消耗估算、改设置、开关自启。

![状态](https://img.shields.io/badge/platform-Windows%2011-0078D4)

## 快速开始

```
python -m pip install -r requirements.txt
python run.py            # 开发期直接跑
```

打包成单文件 exe：

```
build.bat                # 产物在 dist\deepseek-tray.exe
```

双击 exe 即可。**第一次启动会解包到 `%TEMP%`，要等 1–3 秒**，之后图标才出现。

## 托盘图标含义

图标是两个**互相正交**的维度叠出来的，一共 4×2 = 8 张图：

**维度一：余额档位**（颜色 + 形状双重编码，16×16 下也能分辨）

| 图标 | 状态 | 含义 |
|---|---|---|
| 🟢 实心圆点 | ok | 余额 ≥ 偏低阈值（默认 20） |
| 🟡 实心圆加横杠 | warn | 余额 < 偏低阈值 |
| 🔴 实心圆加感叹号 | critical | 余额 < 告急阈值（默认 5） |
| ⚪ 灰色空心环 | error | 取数失败（key 无效 / 网络不通 / 超时） |

**维度二：计费时段**

- **空闲时段** —— 上面这套原图，不加任何东西
- **高峰时段** —— 同样的底图，盖一道**红色斜杠**（左上 → 右下）

斜杠带一圈**深色描边**，这不是装饰：critical 档的底图本身就是红的，不描边的话
红压红完全看不出来；描边用深色而不是白色，是因为 critical 的感叹号是白的，
白描边会和它糊在一起。

斜杠画得比圆长，多出来的部分**按圆裁剪**掉。这样首尾正好切成两段圆弧，既不会
伸进透明的四角在任务栏上留下两截悬空残端，也不用去手调一个"刚好够长又不露头"
的角度（那个值随描边宽度变，很脆）。

时段切换（09:00 / 12:00 / 14:00 / 18:00）跟轮询周期不对齐，所以 `app.py` 里有个
`tier_watchdog` 线程专门睡到下一个切换点再主动刷一次 —— 否则一个专门用来看
"现在是不是高峰"的图标要迟最多一整个轮询周期（默认 5 分钟）才翻。

悬停显示四行：

```
DeepSeek
可用余额 ¥16.79
空闲时段（半价）· 2 小时 13 分后转高峰
21:24 更新 · 431ms
```

出问题时换成：

```
DeepSeek 余额获取失败：API Key 无效或已失效 (401)
上次成功 21:24 更新 · 可用余额 ¥16.79
连续失败 3 次
```

## 右键菜单

- 顶部三行是只读信息：**总量**、**可用余额**、账户状态

  第一行「总量」只是标题，不带数字 —— 它和「可用余额」取的是同一个值
  （接口的 `total_balance`），印两遍没有意义。
- **峰谷时段**（含距下次切换的倒计时）与**当前时段单价**，判定规则见下节
- **今日消耗 / 近 7 日消耗 / 日均 / 预计可用天数**
- **立即刷新** —— 也是左键单击托盘图标的动作
- 复制余额 / 打开数据目录
- **开机自启** —— 勾选态读的是注册表实际值
- 设置… / 退出

## 峰谷时段怎么判断

照抄官方规则（[api-docs.deepseek.com/zh-cn/quick_start/pricing](https://api-docs.deepseek.com/zh-cn/quick_start/pricing)）：

> 空闲时段价格为高峰时段价格的一半。北京时间周一至周五（不含中国法定节假日）
> 9:00 - 12:00、14:00 - 18:00 为高峰时段；其余时段，包括周末及中国法定节假日
> 全天均为空闲时段。

判定在 `deepseek_tray/pricing.py`，三个输入按顺序短路：**周六周日** → 空闲；
**法定节假日** → 空闲；否则落在上面两个窗口里就是高峰。

两个实现取舍：

- 时区用固定的 **UTC+8** 而不是 `zoneinfo` 的 `Asia/Shanghai`。中国全境单一时区，
  且 1991 年后再没实行过夏令时，固定偏移与区域库完全等价，却省掉 Windows 上
  `zoneinfo` 需要额外装 `tzdata` 的依赖。
- 高峰价是**用空闲价 ×2 推出来的**，没有单独存一份。官方规则就是「空闲价是高峰价
  的一半」，现行价目表上每个数字也恰好是两倍（4.5→9.0、13.5→27.0…），只存一份
  才不会两边抄错对不上。

### 每年要维护一次

法定节假日表 `pricing.HOLIDAYS` 要手工更新，数据源是国务院办公厅每年 11 月左右发的
《关于下一年部分节假日安排的通知》。**表里缺哪个年份，那一年的节假日就会被当成
高峰时段**（日志里会 warn 一条）。当前收录：2026 年。

表里只放**放假日**。调休上班的那些周末（2026 年是 1/4、2/14、2/28、5/9、9/20、10/10）
不用列 —— 规则里周末整日都算空闲，列不列结果一样。

## 消耗是怎么算出来的

每次刷新把 `(时间, 余额)` 存一条快照到本地，然后：

```
消耗 = Σ max(0, 前一条余额 - 当前余额)
充值 = Σ max(0, 当前余额 - 前一条余额)
```

**只累加负增量**，所以中途充值不会把消耗算成负数，也不需要任何"检测到充值就重置
基线"的特殊逻辑；正增量之和就是充值额，可以用来自检。

诚实的局限：

- 只在刷新时刻采样。**关机期间的用量会在下次启动时体现为一笔大增量** —— 数值是
  对的（用的就是那些钱），只是时间点归到了那一刻。
- 当天 00:00 到当天首个快照之间的消耗统计不到。
- 当天样本不足 2 条时显示"—"而不是编一个 0 出来。

## API Key 从哪来

按优先级：

1. **设置窗口里手动填的 Key**（留空则忽略）
2. `~/.dsh/.credentials.yaml` 里 `refs.DEEPSEEK_API_KEY` —— 也就是 DeepSeek Harness
   的那份凭据，开箱即用，不用额外配
3. 环境变量（当前版本未启用）

凭据文件是两层 YAML，用正则只匹配 `refs:` 区块就够，所以刻意不引入 PyYAML。

## 数据文件

都在 `%APPDATA%\deepseek-tray\`：

| 文件 | 内容 |
|---|---|
| `config.json` | 配置。损坏时会改名成 `config.json.bad-<时间戳>` 保留证据，再用默认值重建 |
| `balance_history.jsonl` | 余额快照，一行一条。坏行逐行跳过，不影响其余 |
| `app.log` | 轮转日志（1 MB × 4） |

配置写入是"临时文件 + 原子替换"，避免断电留下半截 JSON。历史数据启动时清理
90 天前的记录，超过 2 万行会紧凑重写。

## 命令行

```
deepseek-tray.exe --once       # 只拉一次并打印，不进托盘（排查网络/凭据问题）
deepseek-tray.exe --selftest   # 自检图标、tooltip 长度、自启命令、目录可写
deepseek-tray.exe --debug      # DEBUG 日志
deepseek-tray.exe --autostart  # 由开机自启拉起，首次请求延后 12 秒
```

`--once` 和 `--selftest` 是排查问题的第一站：能把"网络/凭据/解析"的问题和
"托盘 UI"的问题分开。

## 已知问题

**Windows 11 默认把新托盘图标折叠进「^」溢出菜单。** 程序其实跑得好好的，但图标
藏在溢出区里，会被误当成"没生效"。去 `设置 > 个性化 > 任务栏 > 其他系统托盘图标`
把它打开，或者从溢出菜单里把它拖到任务栏上。

**气泡通知可能不显示**，如果开了"专注助手/勿扰模式"。低余额提醒同一档位只推一次，
余额回升再跌回来才会重新提醒。

**单实例**：重复启动不会起第二个图标，而是把已在运行的那份的设置窗口弹出来。

## 实现要点

三条线程，只有两条通道（带锁的 `AppState` 和 Tk 的队列）互相通信：

| 线程 | 干什么 |
|---|---|
| 主线程 | Tk 的隐藏 root 与 mainloop |
| pystray 消息循环 | 托盘图标与菜单（`run_detached()` 起的） |
| 轮询线程 | 定时拉余额 |

**为什么 Tk 占主线程而不是 pystray**：`Icon.run()` 文档要求主线程，但 Tk 也要求，
而跨线程销毁 Tcl 解释器是 `abort` 级崩溃（不是 Python 异常，`try/except` 拦不住）。
所以让 Tk 独占主线程，pystray 走官方支持的 `run_detached()`。

**绝不允许从 pystray 线程或轮询线程直接碰任何 Tk 方法**，菜单回调只能
`gui.post(...)` 把请求塞进队列，由主线程的 `after` 泵取出来执行。

**图标用 BMP 帧而不是 PNG 压缩帧**：Pillow 默认把 ICO 所有帧写成 PNG，而 pystray
用 `LoadImage(LR_LOADFROMFILE)` 加载，这条路径对 PNG 帧不可靠 —— 失败时 `hIcon`
为 NULL、`Shell_NotifyIcon` 的返回码被忽略，**图标静默不出现，一点报错都没有**。
所以用 `bitmap_format="bmp"`（只大十来 KB），并在 `visible = True` 之后自检
`icon._icon_handle` 是否为空并写日志。

**tooltip 会被裁剪**：`NOTIFYICONDATAW::szTip` 是定长 `WCHAR*128`，超长赋值直接抛
`ValueError`。更阴的是 `Icon._notify` 里写的是 `szInfoTitle=title or self.title`，
不显式传 title 就会拿整个 tooltip 去撞 `szInfoTitle` 的 64 字符上限 —— 一个稍长的
tooltip 就能让"余额不足提醒"自己抛异常。所以 tooltip 裁到 118 字符，气泡一律显式
传一个短标题。

**`--noconsole` 下的 stdio**：`print()` 本身在流为 `None` 时是静默 no-op，但
`sys.stdout.write()` 会炸，而且**在流为 None 时创建的 logging StreamHandler 每次
emit 都会炸**。所以日志一律写文件，只在确实继承了控制台时才额外挂 StreamHandler。
另外全部未捕获异常（含各线程和 Tk 回调）都接管进日志 —— 否则打包后崩溃是完全静默的。
